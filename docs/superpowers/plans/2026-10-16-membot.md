# MemBot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native macOS menu bar app and main window that show real-time memory and CPU, group processes under their root, show ports, mark leftover processes as candidates for removal, and send SIGTERM or SIGKILL on a click.

**Architecture:** One Swift package with three targets. `MemBotCore` is pure logic with no OS calls (models, formatting, parsers, the root rule, the status and candidate engine, history, search). `MemBotSystem` reads the OS (libproc, sysctl, Mach, `top`, `launchctl`), sends signals, and runs the `Monitor` actor that turns samples into state. `MemBot` is the SwiftUI app (MenuBarExtra, main window, settings). A future automatic manager uses `MemBotSystem.Monitor` and `MemBotCore` without the UI.

**Tech Stack:** Swift 6.4 (language mode 6), SwiftUI, Swift Charts, ServiceManagement, Swift Testing, SwiftPM. No third-party dependencies.

**Spec:** `docs/superpowers/specs/2026-10-16-membot-design.md`

## Global Constraints

- Target macOS 27 only (`platforms: [.macOS("27.0")]`). Owner's Mac: 48 GB, Apple silicon, macOS 27.0.1.
- No third-party dependencies. libproc, sysctl and Mach are callable from Swift through `import Darwin` (probe confirmed `proc_pid_rusage`, `proc_pidpath`, `proc_pidinfo`, `socket_fdinfo`).
- Do not parse CLI output, except `launchctl list` (each 30 s) and `/usr/bin/top -l 2 -s 1 -stats pid,mem,cpu` (each 5 s, second sample only).
- No App Sandbox. No administrator rights. No privileged helper.
- Signals only to processes of the owner (`getuid()`). For other processes the Term/Kill buttons are disabled with a tooltip.
- SIGTERM: no confirmation. SIGKILL: a confirmation that names the process and pid.
- History in memory only, 10 minutes per process.
- Sample each 1 s while the menu bar panel or main window is visible, each 5 s otherwise.
- Memory values use base 1024 and the label "GB"/"MB" (the same as Activity Monitor; 51539607552 bytes shows as "48 GB").
- Bar colors: below 60% green, 60% to 85% amber, above 85% red.
- `ri_user_time` / `ri_system_time` are Mach ticks. Convert with `mach_timebase_info` (125/3 on this Mac).
- The repo is not a git repository. Task 1 runs `git init`.

## Review Focus

1. **Pid reuse.** A process stops and a new process gets the same pid before the owner clicks Kill. The signal must not go to the new process. `sendSignal` checks the start time first (test in Task 6).
2. **Laptop sleep.** After the Mac wakes, every process looks idle for the sleep time. Without a guard, the candidates list floods at once. A gap of more than 120 s between samples resets the idle clocks (test in Task 4).
3. **`launchctl` or `top` fails or times out.** Orphan detection must fall back to the "seen with a different parent" signal only, and must not mark every launchd child as an orphan. Other-user processes keep `nil` values and do not crash the sums (tests in Tasks 3 and 7).
4. **A process stops during a sample, or its parent is missing from the sample.** The sampler skips it, and the tree treats a missing parent as `launchd` (test in Task 3).
5. **Multiplexer servers.** `tmux` and `herdr` run with `launchd` as parent and own the shells. They must go to Background services, never become orphan candidates (test in Task 3).

### Task 4: Activity tracking, status and candidates

**Files:**
- Create: `Sources/MemBotCore/Activity.swift`, `Sources/MemBotCore/Candidates.swift`
- Test: `Tests/MemBotCoreTests/CandidateTests.swift`

**Interfaces:**
- Consumes: `Snapshot`, `ProcessSample`, `MemBotSettings` (Task 1), `RootGroup`, `ProcessNode`, `isAITool` (Task 3), `formatDuration` (Task 1).
- Produces:
  - `public func processCPUPercents(previous: Snapshot?, current: Snapshot) -> [Int32: Double]` — for each pid with the same `ProcessKey` in both: ΔcpuTimeNs / Δwall ns × 100. When `current` has `cpuPercent` (from `top`), use that value.
  - `public struct ActivityTracker: Sendable { public init(); public private(set) var clockStart: Date?; public mutating func ingest(_ snapshot: Snapshot, cpuPercent: [Int32: Double], settings: MemBotSettings); public func lastActive(_ key: ProcessKey) -> Date? }`
  - `public enum ProcessStatus: Equatable, Sendable { case active, idle(since: Date), candidate(since: Date) }`
  - `public struct Candidate: Identifiable, Sendable { public let key: ProcessKey; public let name: String; public let rootName: String; public let totalFootprint: UInt64; public let idleSince: Date; public let isOrphan: Bool; public let reasons: [String]; public var id: ProcessKey { key }; public var shortReason: String }`
  - `public struct Evaluation: Sendable { public var statuses: [Int32: ProcessStatus]; public var candidates: [Candidate]; public var warmup: (elapsed: TimeInterval, needed: TimeInterval)? }`
  - `public func evaluate(_ groups: [RootGroup], tracker: ActivityTracker, settings: MemBotSettings, ownerUID: UInt32, now: Date) -> Evaluation`

**Rules (the exact measure for "active", my call from the spec):**
- The tracker keeps for each `ProcessKey` a one-minute bucket: start time, CPU time and disk bytes at the start, the socket set at the start, and the highest `top` CPU % in the bucket. A new key gets `lastActive = now` (the idle clock starts at the first sample).
- When a bucket is 60 s or older, close it. The bucket is active if its average CPU ≥ `cpuActivePercent`, or Δdisk > `diskActiveBytes`, or the socket set changed (both non-nil), or the highest `top` CPU % ≥ `cpuActivePercent`. An active bucket sets `lastActive = now`. Then start a new bucket.
- If the gap since the previous `ingest` is more than 120 s (sleep), reset every key to `lastActive = now`, a new bucket, and `clockStart = now`.
- Keys that are not in the snapshot are removed.
- Effective last active of a node = the latest of its own `lastActive` and its displayed descendants'.
- Status: `.active` when `now − effective < 75 s` (one bucket plus the 5 s cadence and slack). Else `.idle(since: effective)`.
- Candidates: walk each group that is `.orphan`, or for which `isAITool(group, names: settings.aiToolNames)` is true. From the group node, go down. A node is a candidate when its `sample?.uid == ownerUID` and `now − effective ≥ limit` (limit = `orphanIdleMinutes` for an `.orphan` group, else `candidateIdleMinutes`, in minutes). Do not go below a candidate. Only the candidate node gets `.candidate(since:)`. Its `totalFootprint` is the node's total. Sort candidates by `totalFootprint`, largest first.
- `warmup` is `(elapsed, needed)` while `now − clockStart < candidateIdleMinutes × 60`, else `nil`.
- Reasons, in this order: `"parent gone"` (orphan), `"was under <lastKnownRoot>"` (orphan with a known root), `"CPU below 0.5% for 47 min"` (limit and `formatDuration`; write the limit without trailing zeros), `"no network or disk activity"` (when `diskBytes` and `sockets` are not nil), `"children idle"` (when the node has children), and `"listens on <port>, no connections"` for each listening socket with no non-listening socket on the same local port. `shortReason` = the first two reasons joined by `" · "`.

**Interfaces:**

- Produces:
  - `public struct MonitorSources: Sendable { var processes: @Sendable () -> [ProcessSample]; var arguments: @Sendable (Int32) -> [String]?; var cwd: @Sendable (Int32) -> String?; var sockets: @Sendable (Int32) -> [SocketInfo]?; var system: @Sendable () -> SystemRaw; var top: @Sendable () async -> [Int32: TopRow]?; var launchdJobs: @Sendable () async -> Set<Int32>?; public static let live: MonitorSources }` (memberwise `public init`).

  - `public actor Monitor { public init(sources: MonitorSources = .live, settings: MemBotSettings, ownerUID: UInt32 = getuid(), now: @escaping @Sendable () -> Date = { Date() }); public func tick() async -> MonitorState; public func update(settings: MemBotSettings); public func history(_ key: ProcessKey) -> [HistoryPoint] }`

**Tick policy:**
1. `processes()` and `system()`. System CPU % from the previous ticks with `cpuPercent(from:to:)` (0 on the first tick).
2. `arguments` and `cwd`: read once for each new `ProcessKey` of the owner. Keep them in a cache. Drop cache entries for ended keys.
3. `sockets`: read for the owner's processes when 5 s or more passed since the last socket read. Use the cached value between reads.
4. `top`: when no `top` task runs and 5 s or more passed since the last start, start one in a child `Task`. The rows of the last completed run fill `footprint` and `cpuPercent` for samples whose `footprint == nil`. A result that is not yet complete is used from a later tick.
5. `launchdJobs`: the same, each 30 s. Keep the last non-nil result. Before the first result, pass `nil`.
6. Build the `Snapshot`, `processCPUPercents`, `tracker.ingest`, `buildForest(…, memory:)`, then `memory.record(groups)`, `history.append`, `evaluate`. Return the `MonitorState`.
